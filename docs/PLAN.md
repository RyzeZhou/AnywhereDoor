# 任意门 AWD（Anywhere Door）· 规划

> 状态：**0.1 Alpha 已发布**（2026-10-01：Core + CLI + GUI 可用，见 [README](../README.md)；本文写于 P0 规划期，阶段方向仍有效）
> 日期：2026-09-29 ｜ 缩写 **AWD**

## 一句话定位

**唤起即跳**：常驻托盘的小工具，按全局热键弹出输入框，到达任意
**本地目录 / 远程目录 / 网站 / 程序**。四类目标各占一页，每页独立收藏。

## 它的来历（这决定了它为什么长这样）

AWD 最早**不是独立软件**，而是**哆啦A梦百宝箱（TBX）内置的一个工具**：
当脚本有结果返回时，抓取返回的目录或文件，点击直接到达。**那个版本没有做出来。**

后来有了 ERF / US / FSY / TBX 这几件设计之后，它的用途变大了 ——
**从"TBX 的一个小工具"升级为整个系列的「到达层」**。

所以现在的 AWD 有两个身份，二者**共用同一套收藏数据**：

- **独立形态**：托盘常驻 + 全局热键 —— 不打开任何东西也能跳
- **集成形态**：将来作为统一文件管理器里的「快捷键直达」

## 与最终形态的关系

在系列的最终形态里，AWD 是**到达层**：

```
外壳层   统一文件管理器（本地 + 远程同一窗口、键鼠优先、紧凑）
 ├ 位置层  ILocation
 ├ 查找层  US（文件名 / 内容 / 文献库）
 ├ 搬运层  FSY + ERF
 ├ 动作层  TBX
 ├ 到达层  ← AWD 在这里
 └ 呈现层  程序启动台（AWD 与外壳共用同一套数据）
```

## 四类目标

| 页 | 目标形态 | 到达方式 |
|---|---|---|
| **本地** | 目录路径 | `explorer.exe` 打开 |
| **远程** | `站点:路径` | **交给 ERF**（`erf:` 协议），**不自己实现 SFTP** |
| **网站** | URL | 默认浏览器 |
| **程序** | exe / 快捷方式 / UWP | `Process.Start`；**UWP 走 `IApplicationActivationManager`** |

## 先做「程序」页（相对早期计划的调整）

原打算四页一起做，**现在决定「程序」页最先做**：

1. **它最独立** —— 不依赖 `ILocation` / ERF / FSY，纯本地
2. **它最痛** —— 现在用"桌面文件夹 + 中图标"凑合，做完立刻有收益
3. **最像"任意门"** —— 其余三页都有替代品，**只有应用网格是真空**
4. **能先验证"收藏 + 摆放"数据模型** —— 后面三页全部复用

### 程序启动台 = 手机式方块网格

Windows 在这个位置是**真空**：同类工具（Flow Launcher、PowerToys Run）全是**搜索式**，
**网格式没有**。两者不可互替 —— 搜索式考"记得名字"，网格式考"**视觉记忆 + 一次点击**"。

借"文件"语义的网格差在哪（Explorer 中图标 + 桌面文件夹）：

| 手机主屏有 | Explorer 中图标 |
|---|---|
| 自由摆放 | ❌ 必须自动排列 |
| 分页 / 分组 | ❌ 只能靠子文件夹 |
| 拖到一起自动成组 | ❌ 只能手动建 |
| 去扩展名、大图标为主 | △ 中图标 48px，名字带 `.lnk` |
| 长按出快速动作 | ❌ 那是"文件"的菜单 |
| 下拉即搜 | △ 对快捷方式不友好 |

### 四个关键实现点

1. **jumbo 图标**：`IShellItemImageFactory::GetImage` 拿 256px（Explorer 自己就这么做）；
   UWP 应用从 `shell:AppsFolder` 枚举。
   **先验证可得性** —— 有些老程序资源里只有 32px，那会影响视觉方案
   （可能统一放进圆角方块里，反而更整齐）
2. **启动分两类**：传统 exe / .lnk 用 `Process.Start`（**注意工作目录**）；
   **UWP 必须用 `IApplicationActivationManager::ActivateApplication`**
   （否则"商店应用点了没反应"，这是同类工具最常见的翻车点）
3. **虚拟化网格**：用 `VirtualizingWrapPanel`，别把几百个方块直接塞进 `WrapPanel`
4. **数据是"应用清单"不是"文件夹"**：
   `{名称, 目标(路径或AUMID), 图标缓存, 分组, 排序位置, 参数}`，存 JSON

## 形态

- **托盘常驻** + 全局热键 → 弹出输入框（**主入口，用完即走**）
- **主窗口**：只在整理收藏时打开

## 技术栈

- **.NET 8 + WPF**（与 ERF 客户端 / FSY / US 一致，人和经验都能复用）
- **全局热键**：`RegisterHotKey` + `HwndSource` + `WM_HOTKEY`
  （独立进程，没有 ERF 在 explorer 进程内那些限制）
- **托盘**：`NotifyIcon`（WinForms 互操作，ERF 有先例）
- **收藏持久化**：JSON，`%APPDATA%\AnywhereDoor\favorites.json`
- 原则：不联网、不常驻大内存、启动快

## 数据与存储（地图 + 偏好 + 图标缓存）

| 位置 | 内容 | 要点 |
|---|---|---|
| `%APPDATA%\AnywhereDoor\maps\<地图名>.awdmap` | **一张地图** = 四页的分组 / 条目 / 配色 / 顺序 | 紧凑二进制；**目录就是清单**（自动扫描），拷走 `maps\` 就是搬走全部布局 |
| 同目录 `<地图名>.awdmap.bak` | 上一版 | 每次写盘前自动留；主文件坏了靠它回退 |
| `%APPDATA%\AnywhereDoor\settings.json` | `{doubleClickOpen, activeMap}` | 只放**与布局无关**的东西：打开习惯 + 当前用哪张地图 |
| `%LOCALAPPDATA%\AnywhereDoor\iconcache\<id>_<size>_t1.png` | 图标缓存 | 机器本地、不漫游、**可随时删了自动重建**；`id` 与路径都由 `target` 现算 |

老仓库（`favorites.json` + `groups.json` + 带 `siteColors` 的 `settings.json`）在首次启动时
自动合成一张「默认地图」，原文件改名成 `*.pre-map` 留档，不删。

地图里一条收藏的字段：`name` / `kind` / `page` / `target` / `arguments` / `workingDir` / `group`。
**不存**的三样都是派生物：`id` = `SHA256(target)` 前 8 位、`iconPath` = 缓存目录 + `id` + 尺寸、
`position` = 条目在该页数组里的下标。

- **分组是条目上的一个字符串字段**（`group`），不是容器；null = 未分类。
  另有 `Groups` 登记表存 `{page, name, color}` —— 分开存是为了让**空分组也能存在**。
  保存地图时把"只在条目上出现过的名字"补进登记表，所以**地图里分组一律显式存在**（顺序才有处存）。
- **布局 = 顺序**：二进制里"先后"就是顺序，不存 `position` 字段；内存模型仍带 `Position`
  （每页各自 0 起），GUI 与 CLI 共用同一口径。程序页是 `WrapPanel` 流式排，窗口宽窄一变排布跟着变。
- 同一个"页"概念两种表示：**二进制里是 1 字节序号**（0..3），**导出的 JSON 里是字符串**
  （`programs/local/web/remote`）—— 只有导出件需要人读。
- **"当前选中哪个分组"不落盘**（视图状态，每次启动回「全部」）；GUI **不监视地图文件**，
  CLI 或手工改完要重启 GUI 才看得见。
- 颜色预设中英对照、GUI 与 CLI 共用一份（`Awd.Core/GroupPalette.cs`），**落盘永远是 RGB 三字节**。
- 导出 JSON 再导入是**无损往返**（实测：同名导入后与原文件逐字节一致，唯一差异是地图名本身）。

## CLI 与 GUI 等效（2026-10-01）

`awd`（`src/Awd.CLI`）现在覆盖 GUI 的整理动作，且**无状态** —— 分组当参数用，跟目录那套逻辑一致：

```
awd group list|add|rename|remove|color <名称> [--page 程序|本地|网站|远程]
awd fav list [--page P] [--group G]        # --group - 只看未分类
awd fav group <id> <分组名|->              # = GUI 把条目拖到侧栏
awd fav add <目标> [--page P] [--kind K] [--group G]
awd fav move <id> <页内位置> | remove <id>
awd group color <名称> 蓝|blue|6|#0000FF   # 十项中英对照预设，见 help
awd map list|show|new|use|rename|remove|export|import|size
```

不等效的只剩三处，都是"GUI 才有"的东西：**拖拽摆位与投放区**（鼠标手势）、
**书签导入**（GUI 窗口）、**站点颜色**（存在地图里，CLI 暂未开命令）。

## 任意门地图（已实现）

**用户要求（2026-10-01）**：布局要能**设置多个**并**各自存成文件**，这个文件叫**「任意门地图」**，
上面记载**四页各自的分组、条目、配色与顺序**；要用**更紧凑的格式**存储。

### 先量过：紧凑的空间在哪（7 条收藏 = 2128 字节）

| 字段 | 占比 | 判断 |
|---|---|---|
| `target` | 28% | 真数据，动不了 |
| `iconPath` | 28% | **纯派生**（缓存目录 + id + 尺寸）→ 不该进文件 |
| `name` | 8% | 真数据 |
| `page` | 7% | 可省：按页分组存，不必每条重复写 |
| `id` | 7% | **可推导**（`SHA256(target)` 前 8 位）→ 加载时现算 |
| `arguments` | 6% | 多数是空串；空串不是 null，所以 `WhenWritingNull` 没省掉它 |
| `kind` / `position` | 11% | 真数据，键名可缩短 |
| 缩进与括号 | ≈28% | 关掉 `WriteIndented` 即省 |

→ 光靠"去派生字段 + 去缩进 + 短键名"就能压到 1/3，**不需要**换编码方式 ——
这是我当初的判断，被用户明确推翻："**紧凑指的是二进制紧凑，不是组成结构的紧凑**"。
最终落点是**紧凑二进制**：实测 7 条收藏 **2128 → 516 字节（4.1×）**。
"文件给人看、可手改"这条原则没有丢，它移到了**导出/导入的 JSON** 上
（`awd map export` 出来的就是带真名、带缩进、中文不转义的 JSON，改完 `import` 回去是无损往返）。
格式带 magic `AWDM` + 版本号，读不出来会明确报错，不会当成一张空地图。

### 动手前拍板的五条（结论）

1. **地图取代了现有三份文件**，成为唯一事实源；`doubleClickOpen` 与"当前用哪张"留在 `settings.json`。
2. **格式 = 紧凑二进制**（用户拍板，见上一节），JSON 退为交换格式。
3. **顺序不需要额外字段** —— 数组先后就是顺序，分组和条目都靠它；`position` 因此不进文件。
4. **坏文件不再静默**：原子写（`.tmp` → 上一版转存 `.bak` → 替换）+ 读失败回退 `.bak` +
   回退不了就抛错且**一个字节都不写**。老仓库里 `GroupStore.Load()` 那个"catch 掉返回空表"
   的坑（一次损坏 = 下一次保存清空全部登记）随 `GroupStore` 一起删掉了。
5. **同一条 `target` 跨页重复**：仍按 GUI 的页内查重，没做全局唯一 —— 实测没撞到，先不动。

### 剩下的风险与已经接住的崩溃

- **GUI 不监视文件**：CLI 或手工改过 `.awdmap`，要重启 GUI 才看得见。
- **两边同时写仍会互相覆盖**：GUI 每次落盘写的是**整张地图**。窗口只认自己打开的那个文件
  （`_docPath`，不再跟着"活动指针"跑），所以别的地图坏了、指针被别人改走，都不牵连本窗口。
- **启动时活动地图读不出来**（断电把 `.awdmap` 零化过，真事）：以前是 `MainWindow` 的字段初始化器
  把它抛出去 → 双击启动的人看到的是"点了没反应"。现在 `App.OnStartup` 先走 `MapStore.TryOpenActive`：
  有能读的图就**换最近写过的那张**照常开工（状态条说清换了谁、**不改活动指针**）；
  一张都读不出来才弹「任意门打不开」对话框，并保留全部文件。
- **VM 本地 `%APPDATA%` 断电会零化**：要害布局要么放共享目录，要么靠 `maps\*.bak` 与导出件兜着。
